# خطة تنفيذ مشروع متجر الحلويات على منصة سلة

| البند | التفاصيل |
|---|---|
| الهدف | متجر حلويات على سلة جاهز للتشغيل: تصميم متجاوب، CSS مخصص، إعدادات كاملة، 5–10 منتجات، SEO، اختبار، إطلاق وتسليم |
| السوق | المملكة العربية السعودية |
| المراحل | التحليل ← التصميم ← التطوير ← المحتوى ← الاختبار ← الإطلاق |
| الجدول الزمني | `01-analysis/timeline.md` |
| تقرير الحالة | `01-analysis/status-report.md` |
| افتراض التصميم الحالي | الخيار (أ): قالب جاهز + CSS مخصص (**قرار معلّق** حتى يعتمده العميل، انظر D-01 في تقرير الحالة) |

## 1. الفريق ومجالات المسؤولية

| الدور | الوكيل | المجلدات |
|---|---|---|
| مدير المشروع | `project-manager` | `01-analysis/`، `07-handover/` |
| مصمم UI/UX ومطور CSS | `ui-css-designer` | `02-design/`، `03-theme-css/` |
| مطور منصة سلة | `salla-developer` | `04-store-setup/` |
| كاتب محتوى ومتخصص SEO | `content-seo-specialist` | `05-content-seo/` |
| مختبر الجودة والإطلاق | `qa-launch-specialist` | `06-qa/`، `07-handover/store-admin-guide.md` |
| صاحب المتجر | **العميل** | يقدّم البيانات والصور، ويعتمد المخرجات، ويُنفّذ بنفسه كل ما فيه حسابات أو كلمات مرور أو وثائق أو بيانات بنكية |

> **تنسيق العمل:** الجلسة الرئيسية تستدعي الوكلاء وتنقل مخرجات كل وكيل للوكيل التالي. الوكلاء لا يستدعون بعضهم مباشرة. `project-manager` يراجع كل مخرج مقابل معيار القبول ويحدّث تقرير الحالة بعد كل مهمة.

**مسار حرج موازٍ لا يتحكم فيه الفريق:** توثيق المتجر وتفعيل بوابة الدفع من سلة. إذا تأخر فقد يؤخر الإطلاق حتى لو اكتمل كل شيء آخر.

## 5. قواعد تطبَّق على كل المهام

- لا اختراع لأي بيانات تجارية (أسعار، مكونات، رسوم، أرقام تواصل، تراخيص). الناقص يُعلَّم بـ `[مطلوب من العميل]` ويُسجَّل في تقرير الحالة.
- الفريق لا يُنشئ حسابات، ولا يُدخل كلمات مرور أو بيانات بنكية أو وثائق رسمية. أي عمل داخل لوحة سلة يتم في جلسة يسجّل العميل فيها الدخول بنفسه.
- لا يُعتمد أي مخرج قبل أن يراجعه `project-manager` مقابل معيار القبول.
- اللغة عربية فصحى مبسطة، والروابط (Slugs) بالإنجليزية.
