## 2. يوم الإطلاق

| ☐ | البند | المسؤول | الدليل |
|---|---|---|---|
| ☐ | فحص أخير سريع للوحة: لا طلبات تجريبية معلقة، لا منتجات أو كوبونات تجريبية | `qa-launch-specialist` | |
| ☐ | **إيقاف وضع الصيانة** (مركز الإعدادات ← عام ← وضع الصيانة) (TC-162) | العميل (بإرشاد `salla-developer`) | |
| ☐ | فتح المتجر من متصفح خاص على الحاسوب، ومن جوال على بيانات الجوال لا شبكة المحل: يظهر المتجر لا صفحة الصيانة | `qa-launch-specialist` | |
| ☐ | فحص الدخان (Smoke): الرئيسية ← منتج ← خيار ← السلة ← موعد ← عنوان ← صفحة الدفع، دون إتمام (TC-163) على M1 وM2 وD1 | `qa-launch-specialist` | |
| ☐ | وسائل الدفع الإلكترونية ظاهرة للزائر العادي | `qa-launch-specialist` | |
| ☐ | GA4 يُظهر زيارات فورية (Realtime) من الفحص | `qa-launch-specialist` | |
| ☐ | **أول طلب حقيقي**: استُلم، ووصل إشعاره للتاجر، والموعد ورسالة الإهداء واضحان، والمبلغ صحيح، وظهر حدث `purchase` في GA4 | العميل + `qa-launch-specialist` | |
| ☐ | (اختياري) طلب حقيقي صغير بمدى ينفذه **العميل بنفسه** ببطاقته للتأكد من الدفع الإلكتروني، ثم يقرر تنفيذه أو إلغاءه واسترداده | العميل | |
| ☐ | روابط المتجر محدّثة في حسابات التواصل الاجتماعي ووصف الواتساب للأعمال | العميل | |
| ☐ | دليل الإدارة `07-handover/store-admin-guide.md` مسلّم | `qa-launch-specialist` | |

**خطة التراجع:** إن ظهر خطأ حرج بعد إيقاف الصيانة (الدفع لا يعمل، أو أسعار خاطئة)، يعيد العميل تفعيل وضع الصيانة فوراً، ويُسجل الخطأ، ويُعاد الإطلاق بعد الإصلاح وإعادة فحص الدخان. إن كان السبب CSS المخصص: يُستعاد آخر ملف سليم من النسخة الاحتياطية أو تُفعّل نسخة الثيم الاحتياطية.
